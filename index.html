prewalk

Use the frontier model for the first edit. Let a cheaper executor finish from a verified start.让前沿模型完成关键的第一步，让更低成本的执行器从已验证起点继续完成任务。

prewalk is a two-phase execution layer for coding agents. The planner explores the repository, writes a bounded plan, completes and verifies task 1, then hands the remaining work to an executor that inherits the trajectory—or receives a durable structured packet when a fresh context is preferred.prewalk 是面向编程 Agent 的两阶段执行层：规划器先理解仓库、制定有边界的计划，并完成和验证第一个任务；随后把剩余工作交给继承完整轨迹的执行器，或者在需要干净上下文时交给读取持久化结构化交接包的执行器。

Its engineering core is a host-independent state machine with atomic checkpoints, one-time route tokens, reject-and-retry validation, planner mutation budgets, fail-closed capability probing and recoverable states. It supports native Codex and Claude Code adapters, so handoffs remain bound to the correct run and can be resumed or reconciled after interruption.它的核心是与宿主解耦的状态机：原子检查点、一次性路由令牌、失败即拒绝并重试的校验、规划阶段修改预算、故障关闭的能力探测，以及可恢复状态。它同时支持 Codex 和 Claude Code 原生适配器，确保交接绑定到正确运行实例，并能在中断后恢复或对账。

ViewAtom

A financial-research Agent built around evidence, time and traceability.围绕证据、时间和可追溯性构建的金融研究 Agent。

ViewAtom treats financial research as an auditable pipeline: research intent and profile, workflow planning, MCP and market-data tools, normalized observations, an evidence pool and verifier, then claims, topic graphs and deliverables. Each finding carries its source, as-of time, fetch time, provenance and citation binding, separating verified facts, observed signals and derived judgments.ViewAtom 把金融研究设计成可审计的完整链路：研究意图与画像、工作流规划、MCP 与市场数据工具、观测结果归一化、证据池与验证器，最后生成结论、主题图和研究交付物。每条发现都绑定来源、数据时点、抓取时间、来源类型和引用关系，明确区分已验证事实、观察到的信号与推导判断。

It models entities, themes, events, catalysts, risks and relationships over time, with recoverable event streams, checkpoints, retries, context compaction and replayable regression cases. Reports can be rendered as structured, cited artifacts with clear gaps and disclaimers—so a market answer can be inspected and reproduced instead of being another untraceable chat summary.系统持续建模公司、行业、主题、事件、催化因素、风险及其时间关系，并提供可恢复事件流、检查点、重试、上下文压缩和可回放回归案例。研究结果可以渲染为结构化、带引用的交付文档，并明确缺口与免责声明，让市场判断可检查、可复现，而不是一段无法追溯的聊天摘要。

AgentTect

A systems course for designing, building and operating production-grade Agents.系统学习如何设计、构建和运行生产级 Agent。

AgentTect follows a complete engineering path: model interfaces, structured outputs and tool calling; MCP, Agent loops, planning, context and memory; state machines and workflow orchestration. It then moves into streaming, concurrency, rate limits, retries, idempotency, checkpoints, recovery, permissions, cost control, observability and evaluation.AgentTect 按完整的工程链路组织课程：模型接口、结构化输出和工具调用；MCP、Agent Loop、规划、上下文与记忆；状态机和工作流编排；再进一步学习流式输出、并发、限流、重试、幂等、检查点、故障恢复、权限、成本控制、可观测性和评测。

Each lesson connects current Agent practices—MCP, durable workflows, event-driven runtimes, long-running tasks and Agent evaluation—to runnable implementations and experiments. The outcome is not another prompt demo, but an Agent that can be inspected, resumed, tested and integrated into a real product.每一部分都把 MCP、持久化工作流、事件驱动运行时、长任务执行和 Agent 评测等前沿实践，落实为可运行的实现与实验。最终学到的不是又一个提示词 Demo，而是能够被检查、恢复、测试并接入真实产品的 Agent 系统。

Open source · C++17 · systems开源 · C++17 · 系统工程P04

C++ Memory Pool Framework

Predictable allocation and reclamation for high-concurrency systems.面向高并发系统的可控内存分配与回收框架。

The framework makes the hard parts of memory management explicit: object ownership, thread-local allocation, contention, cross-thread release, reclamation, fragmentation and large-object reuse. These paths can be composed and tuned independently, so a production service can choose its trade-offs instead of relying on one opaque allocator behavior.这个框架把内存管理中最难处理的部分显式拆开：对象所有权、线程本地分配、竞争、跨线程释放、回收、碎片和大对象复用。各条路径可以独立组合和调优，让生产服务能够明确选择取舍，而不是依赖一个不可解释的分配器行为。

Its advantage is control: less shared contention, clearer object lifecycles, bounded fragmentation and more predictable tail behavior, with the costs of throughput, latency, memory overhead and reuse visible under repeatable workloads.它的优势是可控：减少共享竞争，明确对象生命周期，控制碎片增长，并改善尾延迟的可预测性；吞吐、延迟、内存开销和复用率之间的代价，也能在可重复工作负载下被清楚观察。

tigang-reminder

Commit. Push. 提肛.Commit、Push，然后提肛。

Long coding sessions make one tiny habit easy to forget. tigang-reminder turns every successful commit or push into a playful “提肛” nudge—an intentionally silly reminder to reset your posture before the next task. It runs at the hook boundary, outside Agent context, with no network request or model call.长时间写代码最容易忘记一个小习惯：提肛。tigang-reminder 在每次成功 commit 或 push 后发出一个带点玩笑的“提肛”提醒，让你在下一个任务前重置坐姿。它运行在 Hook 边界之外，不进入 Agent 上下文，不请求网络，也不调用模型。
