Möbius

Switch agents and hand off previous work.在不同 Agent 间切换，查找并交接先前的工作。

Möbius is an Agent Session Hub for Claude Code, Codex, OpenCode, Pi, Grok, and OMP. Sessions are treated as persistent assets: you can search history with local SQLite FTS/BM25, cite earlier steps, and hand off trajectories. Native resume stays with the original harness, while cross-agent handoffs record lineage via explicit references rather than lossy summaries.Möbius 是面向 Claude Code、Codex、OpenCode、Pi、Grok 与 OMP 的 Agent 会话中心。系统把会话当作持久资产：支持用本地 SQLite FTS/BM25 检索历史、引用既往步骤，并在不同 Agent 间交接轨迹。原生恢复始终交由原 Harness 执行，跨 Agent 交接则通过谱系图记录引用关系，而非依赖二次生成的摘要。

Native PowerShell tabs, Markdown notes, and a freeform canvas keep execution, notes, and reference material together. Built with Rust, Tauri, and SQLite, source transcripts remain strictly read-only on disk, and prior history is not injected into new prompts by default.原生 PowerShell 标签页、Markdown 笔记与自由多媒体画布，把终端执行、记录与参考资料放在一起。系统基于 Rust、Tauri 与 SQLite 构建，磁盘上的原始会话文件保持只读，且默认不向新会话注入历史记录。

prewalk

My Codex & Claude Code adaptation: verified handoffs, less repeated exploration.我的双宿主适配：继承探索轨迹，让模型接力少走回头路。

prewalk is a two-phase execution routing layer for coding agents. The planner explores the repository, drafts a bounded plan, and completes and verifies task one. Once verified, remaining tasks pass to an executor that either inherits the full trajectory or receives a durable structured packet when starting with a fresh context is preferred.prewalk 是面向编程 Agent 的两阶段执行路由层。规划器负责理解代码库、制定边界清晰的计划，并优先完成且验证首个任务改动。验证通过后，后续工作交由执行器继续——执行器既可以继承完整的交互轨迹，也可以在需要干净上下文时接收持久化的结构化交接包。

Its core is a host-independent state machine with atomic checkpoints, single-use route tokens, reject-and-retry validation, planner mutation budgets, fail-closed capability probing, and recoverable states. Native Codex and Claude Code adapters bind handoffs to the active run, ensuring work can be resumed or reconciled if interrupted.其底层是一个与宿主解耦的状态机：包含原子检查点、一次性路由令牌、失败拒绝并重试的校验、规划期修改预算、故障关闭的能力探测与可恢复状态。通过 Codex 与 Claude Code 的原生适配器，交接始终绑定在具体运行实例上，任务在中断后仍可恢复或对账。

ViewAtom

Financial research built around checkable sources, timestamps, and evidence.把金融研究做成带来源出处、时间戳与证据链的分析。

ViewAtom organizes financial research into an auditable pipeline: research intent and profile, workflow planning, MCP market tools, normalized observations, an evidence pool, and claim verification. Every finding carries its source, as-of time, fetch time, provenance type, and citation link, helping readers clearly separate verified facts, observed signals, and derived judgments.ViewAtom 将金融研究组织为可审计的工作链路：涵盖意图画像、工作流规划、MCP 市场工具、观测结果归一化、证据池与观点验证。每项发现均标明原始出处、数据基准日、抓取时间、来源类型与引用关联，明确区分已验证事实、观察到的信号与推导出的判断。

It models entities, themes, events, catalysts, risks, and relationships over time, backed by recoverable event streams, checkpoints, retries, context compaction, and replayable regression cases. Reports can be rendered as structured artifacts highlighting citations, evidence gaps, and analytical disclaimers, so market conclusions can be inspected and checked instead of trusted blindly.系统持续对实体、主题、事件、催化因素、风险及随时间变化的关系进行建模，支持可恢复事件流、检查点、重试机制、上下文压缩与可回放的回归测试用例。研究报告可以呈现为带引用的结构化文档，并显式标出信息缺口与免责声明，让市场结论可以被逐项核查，而非不可追溯的聊天文本。

AgentTect

A practical engineering curriculum on building and operating production-grade agents.系统学习如何设计、构建与运行工程级 Agent。

AgentTect covers the practical engineering path for building LLM agents: model interfaces, structured outputs, and tool calling; MCP protocols, agent loops, planning, context, and memory; state machines and workflow orchestration. Later modules explore streaming, concurrency, rate limits, retries, idempotency, checkpoints, recovery, permissions, cost control, observability, and evaluation.AgentTect 围绕生产级 Agent 的工程路径展开：从模型接口、结构化输出与工具调用开始，深入 MCP 协议、Agent 循环、任务规划、上下文与记忆管理，再到状态机与工作流编排。进阶内容涵盖流式传输、并发控制、限流、重试、幂等、检查点、故障恢复、权限、成本控制、可观测性及自动化评测。

Each lesson connects current agent patterns—MCP, durable workflows, event runtimes, long-running tasks, and evaluation—to runnable implementations and experiments. The goal is to move beyond prompt demos to build agents that can be inspected, resumed, tested, and integrated into practical software.每个章节都将 MCP 协议、持久化工作流、事件驱动运行时、长任务执行与 Agent 评测等工程实践，落实为可运行的代码与实验。学习目的不是展示简单的提示词 Demo，而是做出能被检查、能恢复运行、便于测试并能接入实际软件系统的 Agent。

Open source · C++17 · Systems开源 · C++17 · 系统工程P04

C++ Memory Pool Framework

Predictable memory allocation and reclamation designed for high-concurrency workloads.面向高并发场景的可控内存分配与回收框架。

The framework separates memory management into explicit paths: object ownership, thread-local allocation, contention points, cross-thread release, reclamation, fragmentation, and large-object reuse. These paths can be composed and tuned independently, so a service can choose its own trade-offs rather than relying on one opaque allocator behavior.该框架将内存管理中的关键环节显式拆开：对象所有权、线程本地分配、竞争点、跨线程释放与回收、内存碎片以及大对象复用。各条路径可以独立组合与调优，让后端服务能根据自身场景明确做出技术权衡，而不是依赖黑盒分配器的默认表现。

The primary design goal is control: reducing shared contention, clarifying object lifecycles, bounding fragmentation, and keeping tail latencies predictable. The costs of throughput, latency, memory overhead, and reuse ratios remain visible and testable under repeatable workloads.框架的核心优势是可控：减少共享竞争、理清对象生命周期、控制碎片增长，并改善尾部延迟的可预测性。在可重复的基准测试负载下，吞吐量、延迟、内存开销与复用率之间的实际代价都可以被清晰观察与衡量。
